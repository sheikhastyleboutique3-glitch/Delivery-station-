# رصد — نظام إدارة الدليفري والمستودعات

**رصد (Rasd)** يدير حركة المنتجات من المستودع ونقاط الدليفري إلى السائقين والعملاء، ويعرض حالة كل قطعة بنظام ألوان فوري:

| اللون | المعنى |
|---|---|
| 🟧 برتقالي | متاح في المستودع وجاهز للصرف |
| 🟦 أزرق | خارج المستودع (عهدة مع سائق) |
| 🟩 أخضر | سُلّم للعميل |
| 🟥 أحمر | مرتجع تالف / ناقص / مفقود ويحتاج إجراءً |
| 🟪 بنفسجي | مرتجع سليم بانتظار الفرز |

الاسم من «الرَّصد» أي المراقبة والتتبع، وهو قريب من «الرصيد». الشعار عبارة عن خطوط باركود بالألوان الخمسة داخل إطار ماسح ضوئي (`public/icon.svg` و `public/logo.svg`).

## المزايا

- **المستودع بالألوان:** بطاقات للجوال وجدول للحاسوب، وتوزيع كميات كل منتج حسب اللون، وفلترة حسب اللون والاسم وSKU والباركود والفئة والنقطة. الضغط على أي لون يعرض سجل حركاته، والأرقام تتحدث كل 15 ثانية.
- **الصرف والتسليم والإرجاع:** لكل عملية سند برقم تسلسلي قابل للطباعة. السائق يؤكد استلام الصرف من جواله. الإرجاع الواحد يمكن أن يجمع حالات مختلفة (3 سليمة و1 تالفة مثلاً).
- **الفرز والمعالجة:** البنفسجي يُفرز إلى متاح أو تالف. الأحمر يُعاد إتاحته أو يُشطب، وهذا من صلاحية المدير فقط.
- **التسوية:** تقارن ما صُرف للسائق بما سلّمه وأرجعه، وتسجل المتبقي عجزاً عند الحاجة.
- **التحويل** بين نقاط الدليفري، و**مرتجع العميل** بعد التسليم.
- **الباركود:**
  - مسح بكاميرا الجوال (`html5-qrcode`) مع تبديل الكاميرا والفلاش.
  - سكانر USB/Bluetooth يعمل دون النقر على أي حقل، ويعمل حتى لو كانت لغة لوحة المفاتيح عربية.
  - مسح نفس المنتج مرة ثانية يزيد الكمية ولا يكرر السطر.
  - طباعة ملصقات Code128 أو EAN-13 أو QR.
- **تتبع بالقطعة** (رقم تسلسلي لكل قطعة) للمنتجات الغالية، وتتبع بالكمية لبقية المنتجات.
- **واجهة السائق:** تطبيق ويب قابل للتثبيت (PWA). إذا انقطع الإنترنت تُحفظ التسليمات على الجهاز وتُرسل تلقائياً عند عودة الاتصال، دون أن تتكرر.
- **التقارير:** حركة المستودع، وعهدة السائقين، وأداء السائقين، والمرتجعات، والجرد. التصدير إلى Excel وCSV (يظهر العربي صحيحاً في Excel) والطباعة.
- **التنبيهات:** مخزون أقل من الحد الأدنى، وأحمر لم يُعالج، وعهدة متأخرة، وصرف لم يؤكده السائق.

### الموظفون والحضور والرواتب (بالدينار الجزائري)

- **ملف شامل لكل موظف أو سائق:** البيانات الشخصية، وبطاقة التعريف وتاريخ انتهائها، والدور ونقطة العمل، وتاريخ الالتحاق، وحالة العمل (نشط / موقوف / متوقف عن العمل مع التاريخ والسبب)، والمركبة ورخصة القيادة للسائقين.
- **الوثائق والصور:** رفع صور البطاقة (الوجه والخلف)، والصورة الشخصية، والرخصة، والعقد، ومعاينتها وتحميلها وحذفها. تنبيهات قبل انتهاء الصلاحية وبعدها.
- **حضور تلقائي:** السائق يُحتسب حاضراً في أي يوم يستلم فيه بضاعة للتوصيل أو يسلّمها، مع عدد القطع المستلمة والمسلّمة وعدد الطرود. الحضور اليدوي متاح للإداريين وللتصحيح.
- **أنظمة الدفع:**
  - **عمولة بالتوصيل:** لكل قطعة مسلّمة أو لكل طرد (طلب) مكتمل. مثال: 100 قطعة × 200 دج = 20,000 دج.
  - **راتب شهري / أيام عمل:** الراتب الشهري ÷ أيام العمل المعيارية × أيام العمل الفعلية، أو أجر يومي محدد × أيام العمل.
  - **هجين:** أجر الأيام + العمولة.
- **أسعار التوصيل قابلة للتعديل:** سعر افتراضي في الإعدادات (200 دج)، وأسعار خاصة لسائق معيّن أو فئة منتج أو نقطة دليفري. الأولوية: السائق ← الفئة ← النقطة ← الافتراضي.
- **مرتجع العميل يلغي العمولة:** يُدفع للسائق عن كل قطعة يسلّمها، وإذا أرجعها العميل تُلغى عمولتها (مثلاً −200 دج للقطعة).
  - الإلغاء بنفس السعر الذي حُسبت به وقت التسليم.
  - يُسجَّل المرتجع من سند التسليم الأصلي، فلا يمكن إرجاع أكثر مما سُلّم.
  - إذا كان الكشف قد دُفع، يُطرح الإلغاء من الكشف التالي.
  - للسائقين بنظام «لكل طرد»: تُلغى عمولة الطرد فقط إذا أُرجع الطلب كاملاً.
- **السعر يُحفظ لحظة التسليم:** تغيير السعر لاحقاً لا يغيّر المستحقات السابقة. قاعدة البيانات نفسها تمنع تعديل العمولة المسجلة أو حذفها.
- **الكشوف والدفعات:** كشف لكل موظف ولكل فترة (أو لكل الموظفين بزر واحد)، مع مكافأة وخصم، ودفعات (نقداً، CCP، بريدي موب، تحويل بنكي)، والحالة (معلق / جزئي / مدفوع).
  - قاعدة البيانات تمنع كشفين متداخلين لنفس الموظف، وتمنع أن يتجاوز المدفوع الصافي.
  - «إعادة الحساب» تضيف التسليمات التي حدثت داخل فترة كشف موجود.
- **السائق يرى مستحقاته:** قسم «مستحقاتي هذا الشهر» في تطبيقه، للقراءة فقط.
- **الصلاحيات:** الموظفون والوثائق والرواتب للمدير فقط.

## التقنيات

Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 (RTL) · PostgreSQL · Prisma 6 · Zod · جلسات JWT في كوكي `httpOnly` · bcrypt · Vitest

### كيف تبقى الأرقام صحيحة دائماً

1. **`stock_movements` هو السجل الأصلي** ولا يقبل التعديل أو الحذف. Trigger في PostgreSQL يرفض `UPDATE` و`DELETE` و`TRUNCATE`.
2. **`stock_color_balances` و`driver_custody` أرصدة مخزنة** تُحدَّث في نفس Transaction التي تُسجَّل فيها الحركة. قيد `CHECK (quantity >= 0)` يمنع أي رصيد سالب.
3. **الخصم يتم في جملة SQL واحدة مشروطة** (`... WHERE quantity >= n`). لذلك لا يمكن لطلبين متزامنين أن يصرفا آخر قطعة معاً.
4. **مفتاح منع التكرار:** كل عملية تحمل `idempotencyKey`، فإعادة إرسال الطلب (مثلاً عند ضعف الشبكة) لا تسجل الحركة مرتين.
5. **أداة `reconcile`** تعيد حساب كل رصيد من سجل الحركات وتُبلغ عن أي فرق.
6. **سجل التدقيق** مربوط بسلسلة بصمات SHA-256، فأي تلاعب مباشر في قاعدة البيانات يظهر عند الفحص.

مصفوفة الانتقالات المسموحة بين الألوان موجودة في ملف واحد: `src/lib/domain.ts`.

### الخطوة 1: قاعدة البيانات (Neon)

1. ادخل إلى <https://neon.com> وسجّل بحساب GitHub.
2. اضغط **Create project**، واكتب الاسم `rasd`، واختر أقرب منطقة لك (مثل Frankfurt أو Singapore).
3. اضغط **Connect** وانسخ رابطين:
   - **الرابط مع Pooling مفعّل** (يحتوي `-pooler`): هذا `DATABASE_URL`.
   - **الرابط مع Pooling مطفأ**: هذا `DIRECT_URL`.
4. احفظ الرابطين في مكان آمن ولا تشاركهما.

### الخطوة 2: مفتاح الجلسات

ولّد نصاً عشوائياً من 48 حرفاً على الأقل بمولّد كلمات المرور في متصفحك أو في مدير كلمات المرور، ولا تستخدم موقعاً خارجياً لا تثق به. هذا `AUTH_SECRET`. إذا تغيّر لاحقاً فسيُطلب من الجميع تسجيل الدخول من جديد.

### الخطوة 3: إدخال البيانات الأولية (من GitHub مباشرة)

1. في مستودع GitHub افتح **Settings ← Secrets and variables ← Actions ← New repository secret**، وأضف:
   - `DATABASE_URL`
   - `DIRECT_URL`
   - `SEED_ADMIN_EMAIL`: بريدك (اختياري)
   - `SEED_ADMIN_PASSWORD`: كلمة مرور قوية للمدير (اختياري، 8 أحرف على الأقل وفيها حروف وأرقام)
2. افتح تبويب **Actions ← Database ← Run workflow**.
   - اختر `seed`.
   - اختر `true` لتجربة النظام ببيانات تجريبية، أو `false` لنظام فارغ فيه حساب المدير فقط.
3. انتظر العلامة الخضراء ✅. هذا الإجراء نفسه يعمل تلقائياً كل ليلة لفحص تطابق الأرصدة، ويرسل لك GitHub بريداً إذا وجد خللاً.

### الخطوة 4: تشغيل الموقع (Netlify)

1. ادخل إلى <https://app.netlify.com> وسجّل بحساب GitHub.
2. اختر **Add new project ← Import an existing project ← GitHub**، ثم اختر مستودع رصد.
3. Netlify يقرأ إعدادات البناء من `netlify.toml` تلقائياً. قبل الضغط على Deploy افتح **Environment variables** وأضف:

   | المفتاح | القيمة |
   |---|---|
   | `DATABASE_URL` | الرابط مع Pooling من Neon |
   | `DIRECT_URL` | الرابط بدون Pooling |
   | `AUTH_SECRET` | المفتاح من الخطوة 2 |

4. اضغط **Deploy**. بعد دقائق يظهر رابط مثل `https://rasd-xxxx.netlify.app`، وهو رابط HTTPS، والكاميرا تحتاج HTTPS لتعمل.
5. افتح الرابط وسجّل الدخول.

**التحديثات بعد ذلك تلقائية:** كل تعديل يُرفع إلى فرع `main` يُختبر على GitHub ويُنشر على Netlify، والـ migrations الجديدة تُطبَّق أثناء البناء. بياناتك في Neon لا تُمس.

### تثبيت تطبيق السائق على الجوال
افتح الرابط في متصفح الجوال وسجّل الدخول بحساب السائق، ثم:
- **Android / Chrome:** القائمة ⋮ ← «تثبيت التطبيق».
- **iPhone / Safari:** زر المشاركة ← «إضافة إلى الشاشة الرئيسية».

### بدائل أخرى

- **Render (مجاني):** يعمل أيضاً (أمر البناء `npm ci && npm run deploy-build`، وأمر التشغيل `npm start`)، لكن الخدمة المجانية تتوقف بعد 15 دقيقة دون زيارات وتحتاج نحو دقيقة لتعود ([المصدر](https://render.com/free)). استخدم Neon لقاعدة البيانات وليس قاعدة Render المجانية لأنها تُحذف بعد 30 يوماً.
- **خادم خاص (VPS) مع Docker:** ضع ملف `.env` فيه `AUTH_SECRET` و`POSTGRES_PASSWORD`، ثم شغّل:
  ```bash
  docker compose up -d --build
  docker compose exec app npm run db:seed
  ```

## التشغيل على جهازك (للمطورين)

```bash
cp .env.example .env              # عدّل الروابط و AUTH_SECRET
npm install
npm run db:migrate                # إنشاء الجداول
npm run db:seed                   # البيانات الأولية
npm run dev                       # http://localhost:3000
```

| الأمر | الوظيفة |
|---|---|
| `npm run dev` / `build` / `start` | التطوير / البناء / التشغيل |
| `npm run db:migrate` | تطبيق الـ migrations |
| `npm run db:seed` | البيانات الأولية |
| `npm test` | الاختبارات (تحتاج `TEST_DATABASE_URL` لقاعدة اسمها يحتوي `test`، لأنها تُمسح بالكامل) |
| `npm run reconcile` | فحص تطابق الأرصدة مع سجل الحركات |
| `npm run audit:verify` | فحص سلامة سلسلة سجل التدقيق |
| `npm run typecheck` | فحص الأنواع |

الكاميرا تعمل على `localhost` أو عبر HTTPS فقط.

## الوثائق: أين تُخزَّن؟

الملفات تُخزَّن داخل قاعدة البيانات (جدول `employee_document_files`)، فلا حاجة لخدمة تخزين إضافية، والنظام يعمل كما هو على Netlify وDocker.
- الصور تُصغَّر في المتصفح قبل الرفع (نحو 300 كيلوبايت للصورة).
- الحد الأقصى 5 ميغابايت للملف.
- تتسع خطة Neon المجانية (1 GB) لآلاف الوثائق.

## الأمان

- كلمات المرور مجزأة بـ bcrypt (تكلفة 12).
- حد 5 محاولات دخول فاشلة في الدقيقة، ثم قفل 15 دقيقة. المحاولات مخزنة في قاعدة البيانات فتعمل مع أكثر من خادم.
- الجلسة في كوكي `httpOnly` و`SameSite=Lax` و`Secure` في الإنتاج.
- تغيير كلمة المرور أو الدور أو تعطيل الحساب يُخرج المستخدم من كل أجهزته فوراً.
- حماية CSRF عبر ترويسة مخصصة ومطابقة الـ Origin.
- التحقق من كل مدخل بـ Zod، واستعلامات مُعلّمة فقط، ومنع حقن الصيغ في ملفات CSV.
- رؤوس أمان: CSP، وX-Frame-Options، وHSTS، وPermissions-Policy.
- السائق لا يرى سعر التكلفة.
- **تحسين مستقبلي:** سياسة CSP الحالية تسمح بـ `'unsafe-inline'` للسكربتات لأن Next.js يحقن سكربتات داخلية. يمكن تشديدها لاحقاً بنظام nonce.
